## Сниппеты

Сниппет – это именованный кусок конфигурации Sing-box, который хранится один раз и подставляется в любое количество профилей конфигурации по имени.

Когда профилей становится много, любое мелкое изменение превращается в рутину: например, у вас несколько профилей, и во всех одинаковый набор правил маршрутизации (блокировка рекламы, torrent-трафика, обход блокировок). Без сниппетов правку придется повторять в каждом профиле. Со сниппетами вы меняете правило в одном месте, и оно автоматически подтягивается во все профили, которые на него ссылаются.

---

### Формат сниппета

Сниппет – это **всегда JSON-массив объектов**, даже если объект внутри всего один.

```json
[
  {
    "type": "direct",
    "tag": "direct"
  }
]
```

Требования к содержимому:

- это должен быть массив (`[]`), а не объект (`{}`);
- в массиве должен быть хотя бы один элемент;
- пустые объекты (`{}`) внутри массива не допускаются.

---

### Куда можно подставлять сниппеты

В Sing-box сниппет можно подставлять в четыре места. В трех из них это массивы, и ссылка выглядит как объект `{ "snippet": "имя_сниппета" }`. В четвертом – корень конфигурации, и ссылка выглядит как массив имен в поле `snippets`.

#### 1. outbounds[]

Используется для добавления готовых блоков исходящих соединений (например: direct, block, socks, warp):

```json
{
  "outbounds": [
    {
      "snippet": "my-outbounds"
    }
  ]
}
```

#### 2. route.rules[]

Используется для переиспользования правил маршрутизации (блокировка рекламы, торрентов, списков geosite / geoip):

```json
{
  "route": {
    "rules": [
      {
        "snippet": "block-ads-and-torrents"
      }
    ]
  }
}
```

#### 3. endpoints[]

Используется для добавления готовых эндпоинтов (WireGuard, Tailscale и др.):

```json
{
  "endpoints": [
    {
      "snippet": "my-endpoints"
    }
  ]
}
```

#### 4. Корень конфигурации (поле snippets)

В корне конфигурации ссылка задается массивом имен в поле `snippets`:

```json
{
  "snippets": ["dns-cloudflare", "log-preset"],
  "inbounds": [],
  "outbounds": []
}
```

Такой сниппет должен содержать **секции корневого уровня** Sing-box (например, `dns`, `log`, `experimental`). Это по-прежнему массив объектов, где ключи внутри – это названия корневых секций Sing-box:

```json
[
  {
    "dns": {
      "servers": [
        {
          "type": "udp",
          "tag": "dns-cloudflare",
          "server": "1.1.1.1"
        }
      ]
    }
  }
]
```

Секции можно как разложить по отдельным элементам массива, так и собрать в одном объекте:

```json
[
  {
    "log": {
      "level": "info",
      "timestamp": true
    },
    "dns": {
      "servers": [
        {
          "type": "local",
          "tag": "dns-local"
        }
      ]
    }
  }
]
```

---

### Как происходит подстановка

#### В массивах

Объект со ссылкой `{ "snippet": "имя" }` заменяется содержимым сниппета целиком. Если в сниппете несколько элементов – на место ссылки встанут все они.

**Было в профиле:**

```json
{
  "outbounds": [
    { "snippet": "default-fallback-outbounds" }
  ]
}
```

**Сниппет default-fallback-outbounds:**

```json
[
  { "type": "block", "tag": "blocked" },
  { "type": "socks", "tag": "warp-fallback", "server": "127.0.0.1", "server_port": 40000 }
]
```

**Итоговый конфиг на ноде:**

```json
{
  "outbounds": [
    { "type": "block", "tag": "blocked" },
    { "type": "socks", "tag": "warp-fallback", "server": "127.0.0.1", "server_port": 40000 }
  ]
}
```

**Объект со ссылкой заменяется полностью.** Если рядом с `snippet` написать другие ключи, они будут проигнорированы.

Если сниппета с указанным именем не существует в панели, элемент со ссылкой просто удаляется из массива, чтобы не ломать запуск ядра Sing-box.

#### В корне

Все перечисленные в `snippets` сниппеты объединяются в единый набор секций и добавляются в корень конфигурации Sing-box. Поле `snippets` удаляется из итоговой конфигурации перед отправкой на ноду.

Действуют важные правила:

1. **Секции, уже объявленные в профиле, не перезаписываются.** Если в профиле вручную написан блок `log`, а сниппет тоже содержит `log` – останется блок из профиля. То, что задано вручную, имеет наивысший приоритет.
2. **Служебные секции никогда не подставляются.** Это `inbounds`, `api`, `stats`, `metrics` и `snippets` – ими управляет сам Exodus. Если сниппет содержит такие секции, они молча пропускаются.
3. **Порядок применения:** если два корневых сниппета содержат одну и ту же секцию, применится секция из сниппета, указанного позже в списке.

#### Порядок обработки

Сначала обрабатывается корень конфигурации, затем элементы массивов. Благодаря этому корневой сниппет может принести, например, секцию `outbounds`, содержащую ссылки на другие сниппеты — они также будут корректно раскрыты. Вложенность поддерживается на один уровень.
